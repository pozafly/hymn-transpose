# 1~80장 악보 내용 대조

확인일: 2026-09-24. 사용자 요청에 따라 실제 악보 내용과 변환 결과를 대조했다.
이전에 정한 로컬 1~80장 범위를 유지했으며 유닛·E2E 테스트는 실행하지 않았다.

## 확인 결과

| 대상 | 비교 항목 | 결과 |
| --- | --- | --- |
| MuseScore 원본 → 저장된 MusicXML, 79곡 | 보표·성부·마디·시작 위치·음길이·음높이·이명동음 철자·붙임줄 시작/끝, 쉼표, 가사 위치, 조표·박자 | 모두 일치 |
| MusicXML → 앱 내부 악보 데이터, 79곡 | 음표·쉼표·가사·조표·박자 및 붙임줄 시작 | 모두 일치 |
| 수정된 LilyPond 소스 → LilyPond 2.24.4 MIDI, 79곡 | 음높이·시작 시점·지속시간·중복 음 개수, 붙임줄은 이어진 길이로 비교 | 모두 일치 |
| 1~80장 가사 → 한국찬송가공회 홈페이지 | 모든 절의 한글 내용, 띄어쓰기·문장부호 제외 | 265개 절 중 262개 일치, 3개 절 차이 |

79곡의 대조 대상은 음표 16,984개, 쉼표 196개, 가사 부착 항목 13,190개다.
67장은 별도 LilyPond 템플릿이므로 위의 79곡 음표 대조에서 제외했다.
67장의 다운로드 원본과 앱 템플릿 가사 4개 절은 각각 공식 홈페이지와 일치했다.
곡별 절 수도 공식 홈페이지와 일치했다.

이 결과는 다운로드한 악보에서 변환 데이터와 출력 엔진으로 음악 내용이 유지되는지에 대한 확인이다.
인쇄된 정본과 모든 음표를 대조한 결과는 아니다. 이 문서는 먼저 수행한 1~80장 검사의 기록이다.
이후 81~645장 원본 검사·수정은 [645장 원본 검사 기록](source-audit-645.md)에 별도로 기록했다.

## 발견하고 수정한 변환 오류

`lib/musicxml.ts`가 단일 음표의 붙임줄을 음길이 앞에 출력했다.
예를 들어 `d'~2.`는 의도한 점2분음표 붙임줄과 다른 음표열로 해석된다.
`d'2.~`처럼 음길이 뒤에 붙임줄을 출력하도록 수정했다.
화음 내부의 개별 붙임줄(`<c~ e>4`)은 기존대로 보존한다.

1~80장에서 이 출력 패턴은 2·20·27·30·38·49·64·74·79장, 9곡 92개 음표에 있었다.
2장에서 실제 엔진 출력의 차이를 재현했고, 수정 후 79곡 전체의 MIDI 대조가 일치했다.
원조 템플릿, 조옮김 방식, `\paper`와 `\layout`은 변경하지 않았다.

생성된 LilyPond 소스가 캐시 버전에 포함되므로 새 코드로 앱·worker를 빌드해 배포하면
영향받는 결과는 조회 시 새 버전으로 생성된다. 이번 대조에서는 운영 DB·기존 PDF/PNG 캐시를 변경하지 않았다.
서버 반영 시 최신 코드를 받은 뒤 앱·worker를 함께 다시 빌드해야 한다. 위 검사에서는 서버에 배포하지 않았다.

## 방법과 한계

- Docker 볼륨의 원본·MusicXML을 읽기 전용으로 복사해 별도 작업 폴더에서 대조했다. 호스트에서 운영 SQLite를 열지 않았다.
- MuseScore XML, MusicXML을 각각 해석하여 보표·성부·마디·위치를 포함한 음표 항목을 비교했다. 단순 음표 개수 비교가 아니다.
- 엔진 대조는 앱이 생성한 소스의 악보·레이아웃을 유지하고 검사용 MIDI 출력만 추가했다. 음높이를 직접 조옮김하지 않았다.
- 동시 유니즌이 MIDI에서 합쳐지지 않도록 검사용 MIDI의 Staff_performer를 Voice로 옮겼다. 이는 [LilyPond 공식 문서](https://lilypond.org/doc/v2.24/Documentation/notation/midi-channel-mapping.html)의 성부별 MIDI 설정을 따른다. 실제 앱 출력 설정은 변경하지 않았다.
- MIDI는 반복 재생 전의 기보 순서로 비교했다. PDF의 배치·겹침, 이음줄·악상·반복 괄호 등 모든 시각 기호의 보존을 보증하지 않는다.
- 공식 기준 악보의 전곡 음표 데이터나 인쇄본은 확보하지 못했다. 홈페이지 가사 대조가 음표 정확성까지 보증하지는 않는다.
- `pnpm run typecheck`와 `git diff --check`는 통과했다. 유닛·E2E 테스트는 실행하지 않았다.

개인 자료와 상세 대조 기록은 Git 제외 경로 `data/reports/score-audit-80/`에 보관한다.
`comparison.json`, `lyric-comparison.json`, `hymn67-lyrics.json`, `midi-comparison.json`이 결과이며,
`audit.mjs`, `lyrics.mjs`, `render-midi.mjs`, `compare-midi.mjs`가 이번 실제 자료 대조에 사용한 스크립트다.
