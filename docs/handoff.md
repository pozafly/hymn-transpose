# 찬송가 조옮김 서비스 핸드오프

2026년 9월 23일 · @pozafly

## 한 줄 요약

찬송가 악보를 원하는 조(key)로 바꿔서 PDF/PNG로 내려주는 웹 서비스다. 악보 조판은 LilyPond를 서버에서 CLI 프로세스로 실행해서 처리한다.

곡을 고르고 조를 드롭다운에서 선택하면 악보가 바로 나오는 것이 목표다.

## 왜 만드는가

교회 반주자와 찬양팀은 회중 음역에 맞춰 찬송가 키를 내리거나 올려야 한다. 지금은 악보를 손으로 다시 그리거나 이조 악보를 따로 구해야 한다.

사용 환경은 주로 피아노 위 태블릿과 폰이다. 결과물을 링크 하나로 공유하고 어느 기기에서든 열 수 있어야 해서 데스크톱 앱이 아니라 웹으로 간다.

## 이미 있는 것

hymn-transpose 저장소가 있고, CLI로는 완전히 동작한다. 웹 계층만 없는 상태다.

| 경로                    | 역할                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| score/build.py          | 조옮김 + PDF/PNG 컴파일. 핵심 함수는 render(tonic_ly)                   |
| score/hymn67.ly.tmpl    | LilyPond 악보 소스 템플릿 (찬송가 67장, 원조 G♭)                        |
| omr/detect_noteheads.py | 악보 스캔 이미지에서 음표머리 좌표와 음높이 검출 (numpy, scipy, Pillow) |
| Dockerfile              | lilypond + poppler-utils + fonts-noto-cjk 포함                          |
| README.md               | 알고리즘, 한계, 튜닝 파라미터 설명                                      |

현재 사용법은 `python score/build.py --key f --png` 이고, 결과는 `dist/hymn67_f.pdf` 와 `.png` 로 떨어진다. `--key` 는 LilyPond(nederlands) 음이름을 받는다 — 샤은 `-is`(`fis`), 플랫은 `-es`(`ges`, `es`, `bes`).

## 만들어야 할 것

곡 목록, 조 드롭다운, 악보 미리보기, PDF 다운로드를 제공하는 웹 UI와 API.

화면은 둘로 나눈다.

- **일반 사용자** — 곡 선택 → 조 선택 → 미리보기 → PDF 다운로드
- **관리자(운영자 본인만)** — 이미지 업로드 → 검출 오버레이 확인 → .ly 편집 → 저장

## 이미 결정된 설계

아래 네 가지는 이미 검증된 결정이다. 바꾸지 말 것.

1. **음표를 직접 계산하지 않는다.** LilyPond의 `\transpose` 에 맡긴다. 템플릿 하단이 `upper = \transpose ges @KEY@ \upperRaw` 형태다.
2. **`\key` 는 템플릿에 원조(`ges`) 그대로 둔다.** 미리 목표조로 바꿔놓고 transpose를 걸면 조표가 이중으로 조옮김되어 더블샵 범벅이 된다. 실제로 개발 중 겪은 버그다.
3. **코드 심볼은 문자열이라 transpose 대상이 아니다.** 템플릿의 `@I@` `@IV@` `@V@` `@V7@` 플레이스홀더를 `build.py` 의 `chord_labels()` 가 계산해서 치환한다. 이명동음 철자까지 맞춘다 — G♭장조의 IV는 B가 아니라 C♭, F♯장조의 IV는 B다.
4. **조는 화이트리스트로만 받는다.** 사용자가 `.ly` 소스를 직접 입력하게 하지 말 것. LilyPond 소스는 Guile Scheme을 실행할 수 있어서 임의 코드 실행(RCE)이 된다. 관리자 화면에서 `.ly` 편집을 허용한다면 컨테이너 격리, 네트워크 차단, 타임아웃, 메모리 제한을 반드시 걸어야 한다.

## 성능과 캐싱

LilyPond 컴파일은 2코어 2.1GHz 기준 약 7초 걸린다. 느린 게 정상이다. 시동 비용만 1.7초고 나머지는 레이아웃 계산이다.

그런데 (곡 id, 조) 조합의 결과물은 영원히 동일하므로 캐시 히트율이 사실상 100%다. **곡 등록 시점에 12개 조를 미리 전부 렌더링해두면** 사용자 응답은 정적 파일 서빙이라 수십 밀리초로 끝난다. 이 방식을 기본으로 가져갈 것.

온디맨드로 굽더라도 최초 1회만 7초고 이후는 캐시 히트다.

## 제약: 이미지 → 악보 변환은 자동이 아니다

`omr/detect_noteheads.py` 는 음표머리의 **위치만** 검출한다. 이미지 업로드로 `.ly` 를 자동 생성하는 것은 불가능하며, 이번 범위가 아니다.

| 항목                   | 검출 여부                                  |
| ---------------------- | ------------------------------------------ |
| 음표머리 좌표와 음높이 | 검출함                                     |
| 조표                   | 안 함 (E4가 실제로는 E♭4일 수 있음)        |
| 임시표 ♯♭♮             | 안 함                                      |
| 음길이                 | 안 함 (x좌표 간격과 빔 위치로 사람이 추론) |
| 마디선, 붙점, 이음줄   | 안 함                                      |
| 가사                   | 안 함 (OCR 없음)                           |

새 곡 등록은 사람이 검출 결과를 보면서 `.ly` 를 작성하는 반자동 작업이고, 곡당 1~2시간 걸린다. 따라서 초기엔 자주 쓰는 10~20곡만 넣고 시작하는 게 현실적이다.

장기적으로는 [Audiveris](https://github.com/Audiveris/audiveris) → MusicXML → `musicxml2ly` 경로를 검토한다. 이러면 곡당 10~20분까지 줄일 수 있지만 한글 가사는 여전히 직접 입력해야 한다.

## 운영상 함정

- **LilyPond는 라이브러리가 아니라 CLI 프로세스다.** Node에서는 `child_process.execFile` 로 띄우고 타임아웃을 반드시 건다. npm 패키지가 아니라 이미지에 apt로 설치되어 있어야 한다.
- **한글 가사는 CJK 폰트가 없으면 조용히 깨진다.** 템플릿이 `Noto Serif CJK KR` 을 지정하는데 폰트가 없으면 LilyPond가 에러 없이 다른 폰트로 대체해서 네모로 렌더된다. 실패하지 않고 조용히 망가지는 유형이라 결과물 검수가 필요하다.
- **PDF → PNG 변환은 poppler-utils의 `pdftoppm`** 을 쓴다. 없으면 PNG만 안 나오고 PDF는 정상이다.
- **LXC 안에서 도커를 돌리는 구성**이므로 nesting이 켜져 있어야 한다. 기존 스택이 이미 그렇게 돌고 있어서 추가 설정은 불필요할 것으로 보인다.

## 저작권

곡(LYONS, J. M. Haydn 추정 / W. Gardiner 편곡 1815)과 영어 원가사는 퍼블릭 도메인이다.

한글 가사는 한국찬송가공회 새찬송가 수록본이라 개인·예배용 범위를 벗어나는 배포 전에는 확인이 필요하다. 서비스를 공개할 계획이면 이 부분을 먼저 정리해야 한다.

## 1단계로 부탁할 것

Next.js App Router 프로젝트 스켈레톤을 먼저 만든다.

- `/api/render` 라우트에서 `execFile('lilypond', ...)` 실행 (타임아웃 포함)
- 곡 목록과 `.ly` 템플릿을 파일시스템에서 읽기
- (곡, 조) 키로 결과 PDF 캐싱
- 조 드롭다운 + PDF 미리보기 화면 (iframe 또는 PNG)
- 기존 `Dockerfile` 을 베이스로 한 `docker-compose.yml`

이 단계에서는 인증이나 관리자 화면은 뺀다. 곡은 찬송가 67장 하나로 먼저 동작하는 것을 확인한다.
